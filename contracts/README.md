# Contracts

The frozen boundary between the Go runtime, the React package, and every
application adapter.

A protocol described only in prose drifts. Each side reads it slightly
differently, and the differences surface in production as duplicated side
effects after a replay, a transcript that freezes on one missing sequence
number, or a "completed" turn whose last three deltas never arrived. Nothing
here is documentation-only: every file is asserted against by both runtimes.

## What is in here

| Path              | What it freezes                                                                       | Who checks it                                                                       |
| ----------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `schemas/*.json`  | The wire shapes: standard event, journal record, agent-state snapshot, command, error | `go/contracts_schema_test.go`, `packages/use-agent/src/__tests__/contracts.test.ts` |
| `fixtures/*.json` | Golden envelope sequences for deterministic turns                                     | Generated by Go, reduced by the React package                                       |
| `VERSIONS.json`   | Exact dependency versions and artifact checksums                                      | `scripts/freeze-contract-baseline.mjs --check`                                      |

## Fixtures

The fixtures are **generated by the Go runtime** and **consumed by the React
package**. That direction matters: the runtime is the producer of the
protocol, so its output is the artifact, and the client asserts it can reduce
exactly what the server emits.

Regenerate after an intentional protocol change:

```bash
cd go && UPDATE_CONTRACT_FIXTURES=1 go test ./ -run TestStandardEventFixtures
```

Then run both suites. If the Go side changes an event's shape without
regenerating, its own test fails; if it regenerates without the client
agreeing, the TypeScript contract test fails.

Dynamic identity — run ids, message ids, part ids, wall-clock timestamps and
measured durations — is normalized to placeholders (`<run:1>`, `<part:2>`,
`<time>`, `<duration-ms>`). That keeps the files stable across runs while
still proving the identity **relationships**: the same `<part:1>` must appear
in `part.created`, in each of its deltas, and in `part.completed`.

Each fixture is one scenario:

| Fixture           | What it holds still                                                                   |
| ----------------- | ------------------------------------------------------------------------------------- |
| `text-turn`       | Reasoning and text deltas, the accepted user message, one terminal                    |
| `tool-turn`       | Provider-streamed tool arguments, tool output, final response                         |
| `structured-turn` | Tool-emitted semantic status, a structured data-part lifecycle, progress              |
| `hitl-turn`       | An approval request, its decision, and the one-time consumption                       |
| `paused-turn`     | Pause at a safe boundary and a correlated resume, as state events carrying no content |
| `cancel-turn`     | A cancelled run reported as cancelled, never as a success                             |
| `error-turn`      | A provider stream failing mid-part: the part fails, one failed terminal follows       |

## Invariants the tests enforce

These are the properties an assistant is unusable without, so they are
checked on every fixture rather than trusted:

- **Gapless sequence numbers within an epoch.** A gap means the client is
  waiting for an event that will never arrive.
- **Every opened part is closed or failed.** An unterminated part is a
  spinner that never stops.
- **`created → delta(s) → completed` ordering per part.** A delta for an
  unopened part has nowhere to render.
- **Exactly one terminal, and it is last.** Two terminals mean two answers to
  "is this turn over".
- **Replay-stable, unique event ids.** They are the dedupe key across live
  delivery, backfill and reconnect.
- **Bounded error and state payloads.** Prompts, reasoning, tool output and
  tokens must not travel in an error envelope or a state event.
- **No prescribed tenancy in the base contract.** The runtime scopes by an
  opaque token it never parses, and the client's transport authenticates
  against application-defined context. Snapshot and command schemas permit
  extension properties, but AgentKit neither defines nor requires them.
  Guarded by
  `TestNoTenancyModelInTheContracts` (Go) and the "no tenancy model in the
  contracts" block (TypeScript).

## Baseline

`VERSIONS.json` records exact package and Go module versions plus content
hashes of every schema, fixture and built artifact. Regenerate it with:

```bash
node scripts/freeze-contract-baseline.mjs
```

and verify it in CI with `--check`. An unrecorded dependency bump under a
protocol boundary is exactly the change that is hardest to attribute later.
