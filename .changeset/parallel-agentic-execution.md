Parallel agentic execution. Tools can now declare `parallelSafe: true`, marking them safe to run concurrently: when one inference emits multiple tool calls, each maximal run of consecutive `parallelSafe` calls executes as a concurrent batch while every other call stays serialized in model-call order. Determinism is preserved end to end — durable step ids are pre-assigned in model-call order before dispatch (all `step.run`s are created in the same tick, per Inngest's parallel-step rule), results are always fed back to the model in call order (never completion order), `network.state` patches are re-applied in call order after a batch settles, and streaming events publish in call order. Tool errors are captured per call, so one failing tool cannot fail its batch. `agent.run()` also accepts a cooperative `signal: AbortSignal`, checked between execution segments: skipped calls receive a "Tool execution cancelled" error result so every tool_call stays paired with a tool_result.

Networks gain opt-in concurrent subagent dispatch via `parallelAgents: true` (constructor or per-run override): each loop iteration drains the agent stack as one concurrent batch bounded by `maxIter`. Agent run ids, streaming contexts, `state.results` ordering, and per-iteration persistence step ids are all assigned in stack order. If a batched agent throws, successful siblings are still appended and persisted before the first error is re-thrown. Only enable it for agents with non-conflicting scopes — batched agents share `network.state`. Default behavior is unchanged (fully serial).
